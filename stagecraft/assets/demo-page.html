What this page is for and who it is for

This is a demonstration page for Stagecraft, an include file that turns an artifact page into a small self-contained app. It shows every part of Stagecraft (sortable tables, cards that filter, signed rulings, an answer box, tooltips with history, tabs, floating menus) on an invented bakery chain with twelve stores. Nothing on it is real: every store, figure, date and person is made up, so no decision can be taken from it.

It has two readers. A person deciding whether Stagecraft pages suit them looks at how the parts behave. An agent that is about to build a page looks at the page source to see how a part is written. The page is rebuilt by hand whenever the include file changes; there is no schedule and no generator.

Limits: what this page cannot tell you

It tells you nothing about a real bakery: all names and numbers are invented. The Change column is not calculated from the trend, so the two disagree. The region totals are not a comparison of anything real. The Data as of chip always reads stale when the page is opened after 2026-11-18, because that date is typed.

Rulings, answers and comments need the viewer's database and comment capabilities. Opened anywhere else, they are read-only and say so. The page was tested in headless Chrome only; Firefox and Safari were not tried, and neither was a real screen reader or a touch screen.

What you need: this one HTML file and a text editor. There is no generator, no database and no network call, and nothing here needs a tool or an account. To run the page's own checks you also need the skill folder (tests/run_selftest.py opens this page in Chrome and prints PASS or FAIL lines).

Steps, in order:

1. Read the three parts of the include file, marked PB:STYLE, PB:HEADER and PB:SCRIPT. They are a copy of assets/stagecraft-snippet.html. Do not edit them here; change the original and run tests/sync_demo.py.

2. The page content is the HTML between the header part and the script that defines PB_CONFIG. A block belongs to a tab when it carries data-pb-tab with the tab's id; the tabs and their order are PB_CONFIG.tabs. The Log tab is added last by the include file.

3. When you add a figure, say how it was derived in the table "How each figure was derived". When you type in a number or an assumption, add a row to the table "Hard-coded and assumed values" in the same change. Never leave either table behind the page.

4. Keep PB_CONFIG.key (bakery-demo), the table keys, the ask ids and the header texts unchanged, so that readers keep their setup. Add one line to PB_CONFIG.log.versions for each change.
